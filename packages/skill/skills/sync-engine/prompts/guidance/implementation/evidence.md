# Behavioral evidence

Exercise the requested frontend when present; otherwise use the assembled application boundary, typed client, package handler, or real host. Direct concept calls prove concept behavior, not application outcomes.

Reuse sufficient evidence. Add the smallest scenarios that can disprove relevant success, refusal, authorization, repetition, lifecycle, integration, persistence, partial-failure, and recovery commitments. Test compensation by inducing failure and checking later state; test idempotency by repeating one stable operation identity.

Trace every assigned brief outcome to a concrete test and observed result. Structural checks—types, generation, source agreement, and assembly—do not prove caller-visible behavior, persistence, authorization, or recovery.
